# 2026-05-26 — Local predictive loss works, but 50/50 mixing kills it

## The redirect

Dictation 2026-05-26-2 killed the gradient-removal experiments (bridge_detach, warmup_detach). The reasoning: "Does removing gradient make things worse?" is an irrelevant question — you can't have global gradient in the async architecture. Compare against legitimate alternatives instead.

New question: **Does adding a locally-trained interior block improve over a single CE-connected block?**

---

## The experiment

Two-block model. Block 0 gets CE (output block). Block 1 gets only local predictive loss (predict block 0's output via MSE). Detached laterals prevent cross-block gradient. Block 1 sends its representation back to block 0 via a top-down connection (value flows, gradient doesn't).

Config: `topology="top_down_to_first"`, `readout_mode="first"`, `token_injection="block0"`, `detach_lateral=True`, 2K steps, seed 42.

| Condition | Val loss @ 2K | Δ from baseline | Params |
|---|---|---|---|
| Baseline (1 block, CE) | 2.304 | — | 2.85M |
| Control (2 blocks, λ=0, block 1 untrained) | 2.501 | +0.197 | 3.18M |
| Treatment (2 blocks, λ=1, block 1 locally trained) | 2.467 | +0.163 | 3.18M |

[Report](../../experiments/wikitext_103/artifacts/local_predictive/report.json). [Control report](../../experiments/wikitext_103/artifacts/local_predictive_control/report.json).

---

## What this means

The treatment is worse than baseline — but the control isolates WHY:

- **Mixing harm: +0.197.** Adding a 50/50 lateral from block 1 into block 0's input hurts, regardless of whether block 1 is trained.
- **Local loss benefit: −0.034.** The trained block 1 is less harmful than the untrained one. The local loss IS teaching block 1 something useful.

The mechanism works. The architecture's hardcoded `block_input = 0.5 * (own_state + lateral)` is the problem — it dilutes block 0's state with whatever block 1 produces, even when block 1 is unhelpful.

---

## Gated lateral attempt (diverges)

Added a learnable `lateral_mix` parameter (MixAdd, replacing the hardcoded 0.5). Initialized block 0's lateral mix at 0.1 (barely use block 1), block 1's at 0.5 (fully see block 0 for prediction).

Result: training explodes between steps 1000–1500. Val loss goes from 3.05 to 2 billion.

[Gated report](../../experiments/wikitext_103/artifacts/local_predictive_gated/report.json).

The 50/50 mixing is both the problem AND the stabilizer. Lower mixing makes the gradient through the mix parameter too sensitive. The system needs a different approach — possibly layer norm on laterals, gradient clipping, or a fundamentally different mixing strategy (additive rather than interpolation).

---

## Other finding: local loss increases over training

In the treatment run, block 1's local MSE loss *increases* over training (0.109 → 0.151 at 2K steps). Block 0 changes faster (under CE) than block 1 can track. This is the moving-target problem — a known issue in co-training with local losses.

The distributional approach (Wasserstein between predicted and actual distributions, per the architecture README) may address this: the distribution's variance encodes uncertainty, making the loss less sensitive to exact state values.

---

## What's next

The cleanest next step per the think agent's recommendation: **normalization**. Layer-norm both the prediction and the target before computing MSE. This is standard practice to prevent scale explosions AND makes the loss invariant to representation drift (addresses the moving-target problem somewhat).

Alternatively: try an additive lateral contribution (block 0's input = own_state + small_projection(block_1_output)) rather than interpolation. This preserves block 0's full state while adding block 1's signal as a residual.
