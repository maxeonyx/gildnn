# 2026-05-26 — Local lateral communication works on real language

## The headline

A locally-trained interior block **improves** a short-context output block on character-level language modeling. The key variable is **local objective quality** — the objective must target the *exported* representation (last-position hidden state), not all positions.

Staging (training blocks sequentially) is NOT required. Co-training with gradient isolation works slightly better.

## Afternoon: synthetic validation

Split-input test: 100% accuracy when blocks see different inputs. Proves lateral mechanism works with information asymmetry.

Context-asymmetry (co-trained): 12% (chance). Co-training fails with a trivial reconstruction objective on SYNTHETIC random tokens — but the reason turns out to be the objective, not the co-training itself.

Context-asymmetry (staged): 100%. Hard staging rescues the weak reconstruction objective by freezing the representation before lateral learns.

**Intermediate (wrong) conclusion:** "staged training is required." This was overfit to the synthetic task.

## Evening: real language modeling — the correct answer

Experiment: `runs/staged_char_lm.py` on TinyShakespeare (80K train chars).
- Block 0: 8-char context, CE next-char prediction
- Block 1: 64-char context, local objective only
- Lateral: block 1's last-position state → learned projection → additive to block 0 (scale=0.2, gradient detached from block 1)

**Iteration 1 — reconstruction at all positions (FAILS):**

| Condition | Val loss | Δ |
|---|---|---|
| block0_alone | 1.8736 | — |
| staged_lateral | 1.8875 | +0.014 |
| cotrained_lateral | 1.8644 | -0.009 |

Diagnosis: block 1's reconstruction converges to near-zero (0.0002) because self-attention + positional embeddings trivially copies each input token. The last-position state encodes nothing useful about long-range context.

**Iteration 2 — last-position-only next-char CE (WORKS):**

| Condition | Val loss | Δ |
|---|---|---|
| block0_alone | 1.8736 | — |
| staged_lateral | 1.8606 | **-0.013** |
| cotrained_lateral | 1.8563 | **-0.017** |
| shuffled_staged | 1.8848 | +0.011 |

Shuffled control confirms content matters (+0.011 worse than baseline). Real lateral content helps (-0.017 better).

## Evening: multi-block experiments (`runs/multi_block_lm.py`)

Tested whether two interior blocks (ctx=32, ctx=128) are complementary or redundant.

**Initial finding (800 steps) — blocks appear redundant:**

| Condition | val_loss | Δ |
|---|---|---|
| block0_alone (ctx=4) | 1.8561 | — |
| one_block_mid (ctx=32) | 1.8189 | -0.037 |
| one_block_long (ctx=128) | 1.8458 | -0.010 |
| two_blocks (32+128) | 1.8198 | -0.036 |

The long block barely helps. Two blocks ≈ mid block alone. Diagnosis: long block's local CE still high (~1.88) — it hasn't converged on its own local task.

**Capacity ablation:** d_model=128 for long block gives -0.024 (partial improvement). 2 layers gives -0.010 (nothing). Width > depth, but doesn't fully close the gap.

**Pretrain+freeze (4000 steps pretrain, 800 finetune) — blocks become complementary:**

| Condition | val_loss | Δ from 800-step baseline |
|---|---|---|
| one_block_long pretrained | 1.7043 | -0.152 |
| one_block_mid pretrained | 1.6930 | -0.163 |
| two_blocks both pretrained | **1.6567** | **-0.199** |

Pretraining fixes everything: long block helps massively, blocks are complementary (two > either alone). The "redundancy" was entirely a learning dynamics artifact.

**Co-train 4800 steps (final resolution) — no staging needed:**

| Condition | val_loss |
|---|---|
| block0_alone @ 4800 | 1.7115 |
| two_blocks co-trained @ 4800 | **1.6435** |

**Co-training for longer beats pretrain+freeze.** Absolute val_loss: 1.6435 < 1.6567. The system self-organizes given enough training. No staging, no freezing, no tricks needed.

Max described the architecture he actually wants: weight-tied readout (no output projection), addition as the inter-block combination mechanism (IS Bayesian product in log space), and normalization to unit sphere.

Validated piece by piece at tiny scale (`runs/tied_readout_lm.py`):

### A0: Weight-tied readout

Replace `nn.Linear(d_model, vocab_size)` with `logits = hidden @ embedding.weight.T / temperature`.

|---|---|
| block0_alone (tied readout) | 1.7206 |

Works. Essentially no difference from the old readout. One shared embedding serves as both input and output.

### A1: Addition-based combination

**Normalization makes the lateral effect LARGER than the old architecture** (-0.088 vs -0.068 with old learned combiner).

## Night: Recurrent lateral experiment — timing bug and negative result

### The bug (dictation 2026-05-26-6)

Max identified that `recurrent_lateral_lm.py` fed block 1's output to block 0 at the SAME timestep — making them sequential (just a deeper network). The correct design: block 0 at position t receives block 1's output from position t-1 (stale lateral). Both blocks fire in parallel.

The earlier "confirmed" results (mean Δ = -0.058, 3 seeds) measured extra sequential depth, NOT parallel communication.

### Corrected experiment: stale laterals DON'T WORK

Fixed the timing (one-position lateral delay). Results:

**lateral_scale=1.0, 1200 steps, 3 seeds:**

| Seed | block0_alone | recurrent_lateral | Δ |
|---|---|---|---|
| 42 | 1.707 | 1.842 | +0.136 |
| 123 | 1.750 | 2.306 | +0.555 |
| 7 | 1.687 | 1.811 | +0.124 |

All seeds WORSE. Full-scale stale laterals are harmful noise.

**lateral_scale=0.2, 4800 steps, seed 42:**

| Condition | train CE | val_loss | Δ val |
|---|---|---|---|
| block0_alone | 1.553 | 1.611 | — |
| recurrent_lateral | 1.480 | 1.628 | +0.017 |

Neutral at scale=0.2 with 4x training. But the training loss is *lower* for recurrent_lateral — the state IS capturing temporal patterns, but they don't generalize (overfitting).

### Why it fails

Block 1 is trained for local CE (predict its own next-char). It has **no incentive** to produce state useful for block 0 one step later. Without BPTT or temporal credit assignment, the state learns patterns specific to training sequences.

The overlap problem: block 0 at position t sees [t-3, t-2, t-1, t]. Block 1's stale output from t-1 was built from [t-4, t-3, t-2, t-1]. Three of four chars overlap. The only unique information is whatever the state accumulated from distant positions — but detached state is too weak to maintain that.

### Contrast with fixed-window (which works)

Fixed-window block 1 sees 128 chars vs block 0's 4. The information asymmetry is **immediate and obvious** — no temporal accumulation needed. Effect: -0.045 to -0.088 reliably.

## Key insight

**Local CE trains blocks to predict well for themselves, not to communicate.** A block optimized for local prediction has no gradient pressure to store information in its state that's useful for another block at a later timestep. This is the fundamental barrier to stale laterals from detached recurrent state.

## Late night: Multi-rate context buffer experiment — SEQUENTIAL REGIME INCOMPATIBLE

### The hypothesis

The fixed-window approach (tied_readout_lm.py) works by computing the slow block fresh at every position with independent random samples. Multi-rate would instead have the slow block fire periodically (every K positions) and hold its output between firings. Tested whether this amortized version preserves the benefit.

### Results

Script: `runs/multirate_buffer_lm.py`

**Run 1 — lateral_scale=1.0, slow_context=32:**

| Condition | val_loss | Δ | Ablation Δ |
|---|---|---|---|
| block0_alone | 1.6154 | — | — |
| direct_ctx32_refresh1 (control) | 1.6154 | 0.000 | +0.291 |
| buffered_ctx32_refresh8 | 2.2051 | +0.590 | -0.350 (lateral harmful) |

Control TIES baseline — even fresh per-position computation in sequential mode doesn't help.

**Age buckets for buffered condition:**

| Age since refresh | val_loss |
|---|---|
| 0 (fresh) | 1.9402 |
| 1 | 2.1880 |
| 2-7 | 2.22-2.26 |

Even freshly fired is much worse than baseline — the training dynamics are broken, not just staleness.

**Run 2 — rescue attempt with 128-char slow context:**

| Condition | val_loss | Δ |
|---|---|---|
| block0_alone | 1.6410 | — |
| direct_ctx128_refresh1 | 1.6795 | +0.039 |

Even 128-char context (which gives Δ=-0.088 in window-based regime!) fails in sequential mode.

### Why sequential mode breaks the lateral mechanism

In sequential processing, adjacent positions overlap heavily (127/128 for slow block, 3/4 for output block). The slow lateral is nearly constant between consecutive positions. Block 0 experiences it as a static bias — not as position-specific information. In window-based training (tied_readout_lm.py), each sample is independently drawn, so the lateral varies meaningfully and block 0 must use its content.

## Comprehensive finding: what works and what doesn't

| Configuration | Result |
|---|---|
| Fresh per-position lateral, window-based training, 128-char context | **WORKS** (Δ=-0.088) |
| Fresh per-position lateral, window-based training, 32-char context | **Works weakly** (Δ=-0.037) |
| Fresh per-position lateral, sequential training, 128-char context | **FAILS** (Δ=+0.039) |
| Fresh per-position lateral, sequential training, 32-char context | **Fails** (Δ=0.000) |
| Held lateral (buffered), sequential training, 32-char context | **Catastrophic** (Δ=+0.590) |
| Stale recurrent lateral, sequential training, 4-char context | **Fails** (Δ=+0.017 to +0.556) |

The lateral mechanism requires: (1) window-based training, AND (2) fresh computation. Any form of temporal reuse or sequential training breaks it.
