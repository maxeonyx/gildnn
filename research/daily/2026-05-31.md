# 2026-05-31 — Baselines crush the architecture; local objectives explored

## The finding

Standard baselines on the same task (TinyShakespeare character-level, 128-token sequences) expose how far the custom architecture is from competitive:

| Model | CE@1000 steps | Params | Wall time |
|-------|---------------|--------|-----------|
| GRU (2-layer, h=256) | **1.35** | 820K | 8s |
| Transformer (4-layer, d=128) | **1.84** | 825K | 8s |
| Our architecture (192-module graph) | **2.69** | 16M | 220s |

The architecture is 20x bigger, 27x slower, and produces 2x worse CE than a trivial GRU. This contextualizes all local-objectives work: the architecture's multi-module structure currently costs everything and gives nothing back on this task.

Caveats: baselines use batch_size=32 (vs 4 for ours, VRAM-limited by 192 modules), and process all tokens in one forward pass (vs 8 microsteps per token). The fair comparison is wall-clock: in 220 seconds, the GRU completes ~27,500 steps. The gap is enormous.

**Why the gap exists (analysis):**
- Our arch: 8 microsteps × 192 modules per token. Baselines: 2 GRU layers per token. That's ~768x more compute per token.
- Tokens per step: ours 512 (batch=4 × seq=128), baselines 4096 (batch=32 × seq=128). 8x less data per step.
- Total tokens in 220 seconds: ours ~512K, baselines ~110M. Baselines see 215x more data in the same wall time.
- Only 24/192 modules (band 0) contribute to token prediction. The rest (bands 1-7) are supposed to provide multi-timescale context but currently don't.

The architecture's value proposition isn't efficient next-token CE — it's parallel local learning that scales to massive module counts. That value proposition is not yet validated.

## Pretrained embeddings (dictation 07 question)

For character-level modeling with a 65-char vocab and d_stream=96, the token embedding is 6,240 parameters out of 16 million. Standard "pretrained embeddings" (word2vec, GloVe, GPT-2) don't apply to character-level. The embedding learns quickly from scratch — it's not the bottleneck. The closest meaningful experiment: extract learned embeddings from the GRU baseline (which got CE 1.35) and use them to initialize our architecture's embedding. Skeptical it matters given the embedding's tiny size relative to the model and the architecture's structural issues.

## The gradient audit

A new diagnostic (`experiments/automaton_graph/grad_audit.py`) measures CE vs local gradient magnitude per band. At initialization, CE distributes evenly (~6.5 L2 per band) while local loss scales with firing rate — band 7 gets 14× more local gradient than CE gradient:

```

         CE grad    Local grad    Ratio (local/CE)
band 0      6.53         0.00         —  (no local loss)
band 1      6.60         8.54         1.3×
band 2      6.53        12.59         1.9×
band 3      6.55        18.55         2.8×

band 5      6.39        49.62         7.8×
band 6      6.22        69.98        11.2×
```

After 500 steps, the picture collapses further. Attention converges on bands 0-1, so CE gradient to higher bands drops to ~0.27 — a 44× disadvantage vs local loss:

```
After 500 steps:
         CE grad    Local grad    Ratio
band 0      0.63         0.00         —
band 1      0.27        11.71        44×
band 2      0.29        10.42        36×
```

Global gradient cosine between CE and local: **0.013** — effectively orthogonal. The two objectives push in completely unrelated directions. Bands 1-2 got lucky: early CE was proportionally strong enough (1.3-1.9× ratio) to establish token-useful features before attention locked onto them. Bands 3+ never had a window.

## Per-band CE: existence proof, not the solution

**Correction (dictation 2026-05-31-01):** Per-band CE — giving each band a token prediction loss at its own horizon — is an unprincipled hack. It broadcasts a global objective (token prediction) to every level. Max's architecture demands one CE head on band 0 only; everything else learns from local objectives (predicting neighbors, not predicting tokens). Per-band CE is informative as an *existence proof* that the architecture can specialize, but it is not the intended learning rule.

`--per-band-ce` gives band *b* a CE loss predicting the token at `min(2^b, 64)` steps ahead. Gradient stays local. No shared parameters between bands. 30-step sanity check:

```

b1: 3.72 → 3.49  (horizon +2)
b2: 4.00 → 3.64  (horizon +4)
b3: 4.13 → 3.76  (horizon +8)

b5: 4.56 → 4.11  (horizon +32)
b6: 4.33 → 4.05  (horizon +64)
b7: 4.72 → 4.23  (horizon +64, capped)
```

## Fixed readout can't exploit it

A parameter-free test (`experiments/automaton_graph/band_utility.py`) tried combining bands through the model's existing token embedding readout:

```
Band utility (per-band CE step 2000):
  band 0 only:        CE = 2.61
  all bands equal:     CE = 3.21  (WORSE)
```

The fixed readout (normalized dot product against token embeddings) was optimized through CE on band-0 only. Bands 1-7's horizon-specialized features are in a representation space incompatible with this readout. This isn't a deficiency of the bands — it's a readout limitation.

## Confirming the null

MSI + cross-band negatives finished at 2000 steps. Final lag probe: band 0 = 36.7%, band 1 = 21.4%, bands 2-7 = 14-15%. Same as every other configuration that lacks per-band task signal. The input-side and diversity interventions are definitively closed.

## What this tells us

Two boundary conditions, one from each side:

**InfoNCE** (local neighbor prediction) is architecturally correct — each module learns from its neighborhood, no global signal. But it's orthogonal to token prediction (cosine 0.013). It creates structure (orthogonal bands), but structure ≠ useful structure. Generic self-supervised objectives are not automatically good local learning signals.

**Per-band CE** (each band predicts tokens at its own horizon) creates rapid specialization — all bands below entropy in 30 steps. But per the dictation correction above, it's architecturally wrong: it broadcasts a global token-prediction objective to every level. The specialization it produces is real, but the mechanism violates the local-learning principle.

Together they bracket the problem precisely: *what local neighborhood objective is both genuinely local (no global token signal) and task-aligned enough to produce useful multi-timescale representations?*

The anti-token representations in bands 5-7 under per-band CE (scoring below random on token probes) suggest genuine abstraction. Whether this kind of representation can emerge from a truly local objective is the open question.

## Full-stack experiment result (architecturally rejected, diagnostic only)

The capstone experiment (per-band CE + attention readout + detached readout) completed at step 2000. Its premise — per-band CE — is rejected per the dictation above. The result is diagnostic only:

```
Full-stack (step 2000):
  Attention readout CE:  3.03  (WORSE than band 0 alone)
  Band 0 CE:            2.46  (horizon +1)
  Band 1-7 CE:          3.64-4.06  (degraded vs dedicated per-band run)
  Total time:           4452s (~74 min)
```

The learned attention readout (2000 gradient steps, single query attending over 192 module states) could not extract useful next-token information from the per-band representations. Band 0 alone (CE 2.46) is strictly better than the attention combination (CE 3.03). The readout problem is confirmed: even forced specialization doesn't produce representations a simple attention head can exploit for next-token prediction.

## Local objective exploration: predict next-timestep inputs

One candidate local objective: every module predicts what its inputs will be at the next timestep. For band 0 (rate=1), inputs = neighbor_sum + token_embedding. This is genuinely local — no global signal — and forces band 0 to encode token information because tokens are part of what it must predict.

Configuration: `--attention-readout --detach-readout --band0-local-loss`. Modules learn from local prediction only. A detached attention head reads the resulting representations for CE.

```
Band0-local-loss (100 steps):
       prediction_loss
band0:   2.40  ← learning fast (must encode token + neighbor structure)
band1:   4.05
band2:   4.20
band3:   4.18
band4:   3.81  ← timescale separation emerging
band5:   3.69
band6:   3.91
band7:   4.18  (barely fires in 100 steps)

Detached attention CE: 3.24
```

This is below random (4.17) from a head with NO gradient into the modules. Local prediction IS creating token-useful representations in band 0, and the attention head can read them. Compared to per-band CE (3.03 at 100 steps), this starts slower but uses a genuinely local signal.

This is one data point in the local-objectives exploration space, not a settled architecture (see [retraction of dictation 03](../dictations/2026-05-31-04.md)). Other candidates to explore: hierarchical targets (already tested: CE 2.67 at 100 steps), delta prediction, mutual information maximization, contrastive neighbor distinction.

## Where the project ends

The project found the shape of the missing piece and began exploring candidates.

The architecture works: 192 modules, multi-rate bands, detached laterals, noise-driven information hierarchy. The core open question — what local objectives produce good representations in a multi-module system? — is precisely framed but not answered.

Two boundary conditions bracket the answer: InfoNCE (local, orthogonal to tokens) and per-band CE (global, rapid specialization). Between them, "predict next-timestep inputs" shows promise (CE 3.24 from purely local signal), and "hierarchical targets" (CE 2.67) is another viable direction. The space is wide open for future exploration.

Key insight from this project: the local objective must be both genuinely local AND create representations that encode task-relevant information. Neither generic self-supervision nor direct task signal works alone. The answer likely involves the topology — information propagates through the lattice, so band 0's local predictions implicitly encode token structure, which then propagates upward through the neighbor reads.
