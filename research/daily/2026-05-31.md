# 2026-05-31 — Baselines crush the architecture; local objectives explored

## The finding

Standard baselines on the same task (TinyShakespeare character-level, 128-token sequences) expose how far the custom architecture is from competitive:

| Model | CE@1000 steps | Params | Wall time |
|-------|---------------|--------|-----------|
| GRU (2-layer, h=256) | **1.35** | 820K | 8s |
| Transformer (4-layer, d=128) | **1.84** | 825K | 8s |
| Our architecture (192-module graph) | **2.69** | 16M | 220s |

The architecture is 20x bigger, 27x slower, and produces 2x worse CE than a trivial GRU. This contextualizes all local-objectives work: the architecture's multi-module structure currently costs everything and gives nothing back on this task.

Caveats: baselines use batch_size=32 (vs 4 for ours, VRAM-limited by 192 modules), and process all tokens in one forward pass (vs 8 microsteps per token). The fair comparison is wall-clock: in 220 seconds, the GRU completes ~27,500 steps. The gap is enormous.

**Why the gap exists (analysis):**
- Our arch: 8 microsteps × 192 modules per token. Baselines: 2 GRU layers per token. That's ~768x more compute per token.
- Tokens per step: ours 512 (batch=4 × seq=128), baselines 4096 (batch=32 × seq=128). 8x less data per step.
- Total tokens in 220 seconds: ours ~512K, baselines ~110M. Baselines see 215x more data in the same wall time.
- Only 24/192 modules (band 0) contribute to token prediction. The rest (bands 1-7) are supposed to provide multi-timescale context but currently don't.

The architecture's value proposition isn't efficient next-token CE — it's parallel local learning that scales to massive module counts. That value proposition is not yet validated.

## Per-band CE: existence proof, not the solution

**Correction (dictation 2026-05-31-01):** Per-band CE — giving each band a token prediction loss at its own horizon — is an unprincipled hack. It broadcasts a global objective (token prediction) to every level. Max's architecture demands one CE head on band 0 only; everything else learns from local objectives (predicting neighbors, not predicting tokens). Per-band CE is informative as an *existence proof* that the architecture can specialize, but it is not the intended learning rule.

## What this tells us

Two boundary conditions, one from each side:

**InfoNCE** (local neighbor prediction) is architecturally correct — each module learns from its neighborhood, no global signal. But it's orthogonal to token prediction (cosine 0.013). It creates structure (orthogonal bands), but structure ≠ useful structure. Generic self-supervised objectives are not automatically good local learning signals.

**Per-band CE** (each band predicts tokens at its own horizon) creates rapid specialization — all bands below entropy in 30 steps. But per the dictation correction above, it's architecturally wrong: it broadcasts a global token-prediction objective to every level. The specialization it produces is real, but the mechanism violates the local-learning principle.

Together they bracket the problem precisely: *what local neighborhood objective is both genuinely local (no global token signal) and task-aligned enough to produce useful multi-timescale representations?*

The anti-token representations in bands 5-7 under per-band CE (scoring below random on token probes) suggest genuine abstraction. Whether this kind of representation can emerge from a truly local objective is the open question.

## Local objective exploration: predict next-timestep inputs

One candidate local objective: every module predicts what its inputs will be at the next timestep. For band 0 (rate=1), inputs = neighbor_sum + token_embedding. This is genuinely local — no global signal — and forces band 0 to encode token information because tokens are part of what it must predict.

Configuration: `--attention-readout --detach-readout --band0-local-loss`. Modules learn from local prediction only. A detached attention head reads the resulting representations for CE.

This is one data point in the local-objectives exploration space, not a settled architecture (see [retraction of dictation 03](../dictations/2026-05-31-04.md)). ## CORRECTION: hierarchical targets was mislabeled (12:15 NZST)

The earlier "CE 2.67 from purely local signal" was **wrong**. That experiment used `--hierarchical-targets` with the standard band-0 readout (CE gradient into band 0). It was a hybrid: band 0 trained by CE, bands 1-7 trained by hierarchical targets. The reported 2.67 is the standard band-0 CE — essentially the same as the control (2.70) within noise.

The truly purely-local version (`--hierarchical-targets --attention-readout --detach-readout`, where NO band gets CE gradient) gives **CE 3.28 at step 100**. In this config, band 0 is completely untrained (no prediction target for the bottom band, no CE because readout is detached). Only bands 1-7 learn from hierarchical targets.

This means:
- **No purely-local objective has beaten the control.** Best purely-local results: 3.24 (predict-next-inputs), 3.28 (hierarchical targets).
- The "bracketing result" changes: InfoNCE is local but orthogonal (useless), per-band CE is global but effective (2.54), and ALL tested purely-local objectives score 3.2-3.3 from a detached readout.
- The difference between 3.24 and 3.28 is noise. None of the local objectives significantly outperforms any other.

A 1000-step purely-local hierarchical targets run completed. Result: CE worsens from 3.28 → 3.52. Local objectives produce representations that actively diverge from token-useful features. See section below.

## 1000-step purely-local hierarchical targets: definitive negative (12:50 NZST)

The 1000-step run (`--hierarchical-targets --attention-readout --detach-readout`) produced the strongest negative result of the project:

```
Hierarchical targets purely-local (1000 steps):
  step=100  CE=3.28  band2_pred=4.17
  step=500  CE=3.44  band2_pred=2.28
  step=1000 CE=3.52  band2_pred=1.97
```

**CE gets WORSE as local prediction improves.** The modules learn their hierarchical targets beautifully (band 2 prediction: 4.17 → 1.97). But the attention readout finds LESS token information as training proceeds (3.28 → 3.52). The ~3.28 at step 100 was incidental token info from initialization — token embeddings flowing through random GRU weights. As the GRU weights specialize for inter-band prediction, they destroy this incidental token signal.

This is not "local learning doesn't help" — it's "local learning actively hurts." The representations that are good for predicting lower-band means are anti-correlated with representations useful for next-token classification. Same pattern as the 500-step band0-local-loss result (prediction: 4.65→0.54, CE: 3.24→3.41).

**Why this happens (theory):** CE requires features that linearly separate token classes. Local prediction requires features that model neighbor dynamics. These are orthogonal tasks with orthogonal optimal representations. Training for one actively moves the representation away from the other — it's not just "no overlap," it's "active interference." The gradient cosine between CE and local loss (0.013, measured earlier via InfoNCE) confirms: the two objectives push in unrelated directions. "Unrelated" plus training means "actively diverging."

## Theoretical framework: 5 necessary properties (13:00 NZST)

After the 1000-step negative result, a formal theoretical analysis identified 5 properties any successful local objective would need:

1. **Token sensitivity** — the objective's gradient must change depending on the current token
2. **Temporal information preservation** — must incentivize encoding sequence context, not just spatial neighbors
3. **Hierarchical differentiation** — must produce different representations at different rates/bands
4. **Non-degeneracy** — must not collapse to constant or trivial solutions
5. **Downstream usefulness must be locally visible** — the objective must reward representations that are useful for downstream tasks, even without gradient flowing from downstream

All tested candidates (InfoNCE, hierarchical targets, predict-next-inputs) fail property 5 — and the architecture's detached laterals make property 5 structurally impossible for the tested objective family. In a detached architecture, a module cannot observe whether its outputs are useful to its consumers.

The previous session evaluated all known candidate objectives against these 5 properties. None satisfied all 5. Candidates like slow-feature analysis and predictive coding fail on different properties (1 and 5 respectively). See [`research/questions/local-objectives/README.md`](../questions/local-objectives/README.md) for the full evaluation table.

## Literature survey (13:10 NZST)

Quick survey confirms: **purely local learning for competitive sequence prediction is an open problem in the literature.** No published work demonstrates this.

Closest: predictive coding networks (Millidge, Salvatori et al., 2022-2024) approximate backprop gradients locally but explicitly frame PC as converging to backprop's solution. Forward-Forward (Hinton, 2022) is MNIST-only and explicitly preliminary. Blockwise/greedy training (Löwe 2019, Belilovsky 2019) gets within 2-5% of backprop on ImageNet classification but is sequential, classification-only, no sequence prediction.

Our negative result is consistent with the state of the field.

## Where the project ends (corrected final assessment)

The project's central thesis — that local learning through topology creates globally-useful representations — is **not validated**. It is actively contradicted by the evidence:

1. **Local objectives are orthogonal to token prediction** (gradient cosine 0.013)
2. **Local learning actively hurts** token classification (CE worsens from 3.28 → 3.52 over 1000 steps of training)
3. **No tested local objective matches the control** (best purely-local: 3.24; control: 2.70)
4. **The gap doesn't close with time** — it widens

The architecture works mechanically: 192 modules, multi-rate bands, detached laterals, efficient training via CUDA graphs. But the learning rule that would make it useful for language modeling does not exist among the tested candidates.

**What would rescue the thesis:**
- A local objective whose optimal features are linearly decodable as token logits (not tested, not obvious what this would be)
- Allowing some non-local gradient (but this defeats the thesis)
- A fundamentally different topology or communication mechanism
- A different task where local prediction IS aligned with the evaluation metric

The project narrows the design space significantly: generic self-supervision (InfoNCE), neighbor prediction (default), hierarchical prediction (band k → k-1), and input prediction (band0-local-loss) are ALL confirmed failures for token-prediction readout. Whatever local learning rule works for language modeling, it's not in this family.

## Pathway 1: Weight tying (14:00 NZST)

The gating question from PLAN.md: "With ordinary global training, does this architecture family buy any real advantage?" Specifically: **does weight tying hurt at matched FLOPs, and can width compensate?**

### Experiment design

Two models, identical at initialization (deepcopy from same base block):
- **Tied:** 1 pre-LN causal transformer block applied 8 times (Universal Transformer style)
- **Untied:** 8 distinct pre-LN causal transformer blocks, each applied once

Shared: d_model, 4 attention heads, d_ff=4×d_model, Adam lr=3e-4, grad clip 1.0, 1000 steps, 3 seeds. Eval on fixed val batch of 256 samples. LayerNorm parameters tied in the tied model (no sneaky per-depth params).

Script: [`experiments/weight_tying/tied_vs_untied.py`](../../experiments/weight_tying/tied_vs_untied.py)

### Results

| Model | d_model | Params | Val CE (mean ± std) |
|-------|---------|--------|-----|
| Tied | 128 | 230K | 2.070 ± 0.020 |
| Tied | 192 | 493K | 1.899 ± 0.006 |
| **Tied** | **256** | **854K** | **1.788 ± 0.008** |
| Untied | 128 | 1.6M | 1.866 ± 0.003 |
| Transformer 4L (baseline) | 128 | 825K | ~1.84 |
| GRU (baseline) | 256 | 820K | ~1.35 |

### What this shows

1. **At matched FLOPs (same d=128, same depth):** untied wins by 0.20 nats. Extra per-layer capacity matters.

2. **At matched params (~850K):** tied d=256 beats untied d=128 AND the 4-layer transformer baseline. Width compensates for the tying constraint — and then some.

3. **Per-param efficiency of weight tying ≈ 3×.** Tied at ~550K params matches untied at 1.6M params (crossover around d=200).

4. **The tied model's FLOP cost:** Tied d=256 uses 4× the FLOPs per token as untied d=128 (larger block applied same number of times). The param savings come at a compute cost. The value is: fewer params (memory), dynamic depth (iterate less on easy tokens), and potential for parallelism across tokens.

### Comparison to Pathway 1 hypothesis

ROADMAP asks: "Can a single set of weights applied recurrently N times develop the same representational capacity as N distinct layers?"

**Answer: Yes, with width compensation.** At d=256 (8 iterations), the tied model matches and exceeds the untied 8-layer model at d=128 — with half the parameters. The thesis is directionally validated.

**Remaining limitation:** Both are still worse than the GRU (1.35). But this is a different comparison — the GRU has token-to-token sequential recurrence (an inductive bias perfectly suited to next-character prediction), while these models use fixed-context attention. The tied transformer's advantage is parallelizability and dynamic iteration, not absolute quality on this small task.

### Iteration scaling (14:30 NZST)

With the tied d=256 model (854K params), how does quality scale with iteration count N?

| N | Val CE | Δ from N=2 | FLOPs vs untied-d128-N8 |
|---|--------|-----------|------|
| 2 | 1.845 | — | **1.0×** (same!) |
| 4 | 1.802 | -0.043 | 2× |
| 8 | 1.788 | -0.057 | 4× |
| 16 | 1.769 | -0.076 | 8× |
| 32 | 1.740 | -0.105 | 16× |

(N=2,32: single seed; N=4,8,16: 3-seed mean)

**Key findings:**

1. **Width beats depth at matched FLOPs.** Tied d=256 N=2 (1.845) beats untied d=128 N=8 (1.87) at identical FLOPs and half the parameters. A wider shallower model is strictly better.

2. **Logarithmic iteration scaling.** Each doubling of N gives ~0.02-0.04 nats. Most quality comes from the first 2-4 iterations. Later iterations have strong diminishing returns.

3. **Stable through 32 iterations.** No gradient explosion, no quality degradation. Pre-LN + grad clip 1.0 is sufficient for stability.

4. **Dynamic depth has huge headroom.** If tokens only need N≈2-4 on average (getting 95% of N=32 quality), but hard tokens get N=16-32, that's a 4-8× compute reduction on average with minimal quality loss.

### Comparison to ROADMAP "evidence that would increase confidence"

> "A wide recurrent model matching transformer val_loss at equal parameters/FLOPs" → ✓ Tied d=256 N=2 beats untied d=128 N=8 at same FLOPs

> "Stable training through 8, 16, 32+ iterations without gradient explosion" → ✓ Confirmed through N=32

Mean optimal N (within 0.05 of best): **5.07**. 95th percentile: **8**.

**Interpretation — two levels:**

At the **per-token level**, many individual tokens genuinely benefit from later iterations. Only 12% of tokens are "done" at N=2 (within 0.1 nats of their best). Mean optimal N is 5.

**What this means for dynamic depth:**
- Moderate headroom, not extreme. A threshold-based early exit could save ~30-40% of compute (stopping at N≈5 on average), but cutting to N=2 for most tokens is too aggressive.

### Dynamic depth demonstration (16:30 NZST)

Can we actually exit early and save compute? Script: [`experiments/weight_tying/dynamic_depth.py`](../../experiments/weight_tying/dynamic_depth.py)

**Method:** Train tied d=256 N=8 as before. At inference, after each iteration k, compute per-token CE. If a token's CE doesn't improve by more than `threshold` from the previous iteration, that token "exits" — keeps its current logits, stops updating. This simulates per-token dynamic depth.

**Results (CE-based early exit):**
```
Threshold | Mean iters | Val CE | Compute saved | CE overhead
0.001     | 5.73       | 1.752  | 28.4%         | -0.015 (BETTER!)
0.010     | 5.58       | 1.755  | 30.3%         | -0.012 (BETTER!)
0.050     | 5.08       | 1.775  | 36.4%         | +0.009
0.100     | 4.58       | 1.812  | 42.7%         | +0.045
0.200     | 3.84       | 1.900  | 52.0%         | +0.134
```

**Oracle per-token optimal N distribution:**
```
N=1: 17.5% | N=2: 6.8% | N=3: 8.4% | N=4: 8.5%
N=5: 8.0%  | N=6: 8.6% | N=7: 12.8% | N=8: 29.5%
```

**Three key findings:**

1. **Early exit IMPROVES quality** at small thresholds. The model's later iterations overfit to training data — stopping early on validation acts as regularization. This is both useful and informative: the model doesn't need all 8 iterations for most tokens.

2. **42.7% compute savings with +0.045 nats loss** (Pareto point at threshold=0.10). This is the practical operating point: nearly half the compute saved with negligible quality impact.

3. **17.5% of tokens are trivially easy** (done at N=1). These are predictable-from-context tokens where even one iteration is sufficient. 29.5% genuinely need all 8 iterations.

**Connection to Pathway 5:** This demonstrates dynamic depth is feasible for the tied architecture. A properly trained system (with a halting mechanism integrated into training, rather than post-hoc thresholding) could likely do even better — the model would learn to front-load computation knowing that early exit is possible.

**Entropy-based exit (no ground truth):** Also tested using prediction entropy as exit criterion (deployable — no target needed). At ~5.5 mean iterations: val CE 1.92, +0.15 nats overhead. Less efficient than CE-based (which uses ground truth), but demonstrates the approach works without oracle information.

## Learned halting predictor (afternoon — Pathway 5 extension)

**The gap bridged.** A tiny MLP (261→64→1) trained on the frozen model's hidden states predicts remaining CE gain `g_d = L_d - L_8` at each depth. This is the deployable version of oracle exit — no ground truth needed at inference time.

**Architecture:** Input = LN(h_d) + normalized depth + entropy + entropy drop + logit margin + hidden change magnitude. Huber loss, 500 steps on 80% of validation, evaluated on held-out 20%.

**Results (comparison at key operating points):**

```
Method                    | Mean Iters | Val CE | Compute Savings | CE Overhead
Full depth (N=8)          |       8.00 | 1.764  |           0.0%  |    +0.000
Fixed depth 6             |       6.00 | 1.821  |          25.0%  |    +0.057
Learned (hidden) thr=0.05 |       6.12 | 1.764  |          23.5%  |    -0.000 ← ZERO overhead!
Learned (hidden) thr=0.10 |       5.53 | 1.787  |          30.9%  |    +0.023
Oracle CE-based thr=0.10  |       4.58 | 1.811  |          42.7%  |    +0.046
Learned (hidden) thr=0.20 |       4.71 | 1.845  |          41.1%  |    +0.081
Entropy heuristic (best)  |       7.32 | 1.790  |           8.5%  |    +0.025
```

**Three findings:**

1. **Hidden state contains strong halting signal (Pearson r=0.53).** Per-depth r = 0.31–0.40, strongest at depths 3–5 where the decision matters most. Entropy alone is nearly useless per-depth (r=0.02–0.07), confirming hidden state is doing the work.

2. **23.5% savings at ZERO quality cost.** At threshold 0.05, the learned predictor saves compute while matching full-depth CE exactly. Below this threshold, it actually *improves* CE (regularization effect — same as oracle).

3. **85–96% oracle efficiency** at practical operating points. At threshold 0.10: 30.9% savings vs oracle's 36.5% at matched overhead → 85% efficiency. At threshold 0.20: 41.1% vs 42.7% → 96% efficiency.

**Hidden state >> entropy for per-token decisions.** The entropy-only predictor (same architecture, 4 input dims instead of 261) achieves only r=0.42 overall and 30% oracle efficiency. The hidden state encodes information about *which* tokens will benefit from more iterations that is invisible in the output distribution statistics.

**What this means for Pathway 5:** Dynamic depth is not just feasible — it's *practical* with a frozen-model probe. The natural next step is joint training (model + halting head simultaneously), which should be even better because the model can learn to produce clearer halting signals.
