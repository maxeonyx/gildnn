# Project summary — The architecture is built. The local learning rule is not.

The project ran 10 days (May 20–31). It started from "does any piece of this work?" and ended at a precise open question: what local neighborhood objective creates multi-timescale representations that help token prediction, without broadcasting a global objective to every module?

The architecture is built and each piece has been tested. But local learning — the core thesis — remains unsolved. Two boundary conditions bracket the missing piece.

---

## Architectural pieces (prior weeklies have full evidence)

These were validated in weeks 1–3. Full results with inline artifacts are in the weekly reports for [2026-05-21](2026-05-21.md), [2026-05-23](2026-05-23.md), [2026-05-28](2026-05-28.md), [2026-05-30](2026-05-30.md).

These pieces are tested individually and in small combinations. Whether they cooperate at scale under local learning is not yet answered.

## Baseline comparison (day 10)

Standard models on the same task (TinyShakespeare char-level, 128-token sequences) expose the efficiency gap:

| Model | CE@1000 steps | Params | Wall time |
|-------|---------------|--------|-----------|
| GRU (2-layer, h=256, batch=32) | **1.35** | 820K | 8s |
| GRU (batch=4, fair comparison) | **1.74** | 820K | 11s |
| Transformer (4-layer, d=128, batch=32) | **1.84** | 825K | 8s |
| Transformer (batch=4, fair comparison) | **2.32** | 825K | 12s |
| Our architecture | **2.69** | 16M | 220s |

Even at batch=4 (the same batch size our architecture uses due to VRAM limits), the GRU still beats our architecture by nearly a full nat. The gap is architectural, not a batch-size artifact.

The architecture is 20x bigger, 27x slower, and 2x worse. Per token processed: our architecture does ~768x more compute (8 microsteps × 192 modules) than the GRU (2 layers × 1 step). In equal wall time, baselines see ~215x more data.

This doesn't invalidate the architecture's goals — its value proposition is parallel local learning at scale, not efficient supervised next-token prediction. But it contextualizes all local-objectives work: even a perfect local learning rule faces an enormous efficiency gap vs standard architectures on this proxy task.

## The local learning saga

This is the core story. Each attempt narrowed what the local objective must be.

**InfoNCE** — genuinely local, each module predicts its neighbors' representations contrastively. Architecturally correct per Max's vision. But its gradient is orthogonal to token prediction:

```
Gradient cosine between CE and InfoNCE: 0.013 — effectively orthogonal.
```

The lag probe after 5000 steps confirms the failure — only band 0 learned anything token-useful:

```
Lag probe (InfoNCE, step 5000):
       lag=  1 lag=  2 lag=  4 lag=  8 lag= 16 lag= 32 lag= 64
band0:  33.5%  23.5%  19.6%  16.0%  13.6%  13.6%  13.8%
band1:  17.4%  16.1%  16.3%  15.4%  14.9%  14.4%  15.0%
band2:  14.6%  14.8%  15.3%  14.7%  14.3%  15.0%  15.5%  (random: ~14-15%)
band5:  14.6%  15.8%  12.9%  13.2%  13.1%  12.4%  12.4%
```

InfoNCE trained the local predictors (local loss went down) without forcing representations to encode task-relevant temporal information. The loss is local and healthy — just orthogonal to what matters.

**Multi-scale input, cross-band negatives, temporal targets** — all null. The problem is not the input encoding or diversity. It's the prediction target itself.

**Gradient audit** — even if global CE could help, it can't reach higher bands. The local loss drowns it:

```
After 500 steps of attention readout:
         CE grad    Local grad    Ratio
band 0      0.63         0.00        —
band 1      0.27        11.71       44×
band 2      0.29        10.42       36×
band 3-7:  0.26-0.30    3-11       18-44×
```

**Per-band CE** — each band predicts the token at horizon min(2^b, 64). All 8 bands below entropy within 30 steps:

```
Per-band CE (step 30):
b0: 3.24  (horizon +1)     b4: 3.82  (horizon +16)
b1: 3.49  (horizon +2)     b5: 4.11  (horizon +32)
b2: 3.64  (horizon +4)     b6: 4.05  (horizon +64)
b3: 3.76  (horizon +8)     b7: 4.23  (horizon +64)
Entropy baseline: 4.17
```

Existence proof that the architecture CAN specialize. But [dictation 2026-05-31-01](../../dictations/2026-05-31-01.md) rejects per-band CE: it broadcasts a global token-prediction objective to every level. One CE head on band 0, local learning for everything else — that's the design constraint.

**Fixed readout can't exploit specialization** — band utility test with per-band CE checkpoint: band 0 alone gives CE 2.61, adding any other band makes it worse (3.09–3.49). A full-stack experiment (per-band CE + learned attention readout, 2000 steps) confirmed this:

```
Full-stack attention readout (step 2000): CE = 3.03
Band 0 alone:                             CE = 2.46
```

Even with 2000 gradient steps training an attention head over all 192 module states, the readout could not extract useful next-token information from the per-band representations. The readout problem is real regardless of which local objective creates the specialization.

---

## The bracketing result

InfoNCE and per-band CE bracket the missing piece from opposite sides:

- **InfoNCE:** local, architecturally correct — but orthogonal to the task. Modules learn to predict neighbors without encoding temporal information useful for token prediction.
- **Per-band CE:** task-aligned, rapid specialization — but not local. A global objective broadcast to every level.

Together they define the question precisely: what local neighborhood objective is both genuinely local (no token prediction signal broadcast) AND task-aligned enough to create representations that differ across timescales?

## Theory exploration and day-10 experiments

After surveying the design space (see [research/questions/local-objectives/](../questions/local-objectives/README.md)), several candidates were tested on the final day. Max's directive ([dictation 2026-05-31-04](../../dictations/2026-05-31-04.md)): explore many local objectives, don't settle on one.

**Hierarchical targets** (`--hierarchical-targets`): band _k_ predicts the mean state of band _k-1_. 100-step result:

```
Hierarchical targets (100 steps):
  Detached attention CE: 2.67
  Band 0 prediction loss: 2.59
  Bands 1-7: 4.28-4.66
```

CE 2.67 from a detached head — the best purely-local result. But this may be cheating slightly: predicting the mean of a lower band is highly correlated with predicting your own neighbors (since lower-band modules ARE your neighbors in the 2D grid). Needs more analysis.

**Predict-next-inputs** (`--band0-local-loss`): band 0 predicts neighbor_sum + token_embedding. All other bands predict neighbor_sum (unchanged). 100-step result:

```
Band0-local-loss (100 steps):
  Detached attention CE: 3.24
  Band 0 prediction loss: 2.40 (learns fast — must encode tokens)
  Bands 4-6: 3.69-3.91 (timescale separation emerging)
  Bands 1-3, 7: 4.05-4.21
```

CE 3.24 from purely local signal. Band 0 learns rapidly because tokens are part of what it must predict. The token-information propagates through the lattice into higher bands.

Both are one data point each. The 500-step variant of band0-local-loss is running at time of writing. Neither is settled as "the" approach.

## What a future session picks up

**Core question:** what local objectives produce good representations in a multi-module system? ([dictation 2026-05-31-04](../../dictations/2026-05-31-04.md)) This is an exploration space — try many things.

**Candidates tested:**
| Objective | CE (100 steps) | Status |
|-----------|---------------|--------|
| InfoNCE (neighbor prediction) | N/A (orthogonal) | Failed |
| Per-band CE (per-band token prediction) | 2.54 at 2000 steps | Rejected (not local) |
| Hierarchical targets (predict lower band mean) | 2.67 | Promising, needs analysis |
| Predict-next-inputs (band 0 predicts token+neighbor) | 3.24 | Promising, needs longer runs |
| Combined (band0+hier+attn+detach) | 3.35 | Worse than parts individually |
| Control (no local loss, 100 steps) | 2.70 | Matches 1000-step wall |

**Unexplored candidates:** delta prediction (predict state changes), mutual information maximization, contrastive neighbor distinction, phase-amplitude coupling, communication through coherence.

**What's built:**
- `core/automaton_graph.py` — 192-module 2D graph, multi-rate bands, detached laterals, refractory messaging, hierarchical targets, band0 local loss
- `core/triton_forward.py` — fused forward kernel (forward only)
- Diagnostics: lag probe, band similarity, band utility, gradient audit
- Training infrastructure: systemd services, checkpointing, streaming TBPTT

**Key constraint:** the signal must be local (neighborhood-only), must create representations that differ across timescales, and must produce useful representations readable by an external head.

## Honest assessment

The architectural pieces work individually. Several are clean results — detached laterals beating global backprop, multi-rate as a time/quality tradeoff, width scaling outperforming depth. The 192-module graph runs and learns.

The central thesis — local learning creating cooperating multi-timescale representations — is not validated but is no longer pure speculation. Two purely-local objectives (hierarchical targets, predict-next-inputs) produce CE below random from a detached readout head. The question has shifted from "can local learning work at all?" to "which local objective creates the best representations?" That's a narrower, more tractable question with a clear experimental methodology (try candidates, measure detached-head CE).

The project narrowed from "does any of this work?" to "what should the local signal be?" — with an architecture ready to test answers and two promising candidates already showing life.
