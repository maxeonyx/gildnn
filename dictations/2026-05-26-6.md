# Dictation 2026-05-26-6

## The recurrent lateral experiment is wrong

The recurrent_lateral_lm.py experiment has block 1's output being added to block 0's hidden at the **same timestep** before predicting the same target. That means block 0 is waiting for block 1 — they're sequential. It's just a deeper network with extra steps.

The whole point of the parallel architecture is that blocks fire **concurrently and independently**. Laterals must be stale — from the previous timestep. Block 1 at position t produces a lateral, block 0 uses it at position t+1. Both blocks can run simultaneously at position t without waiting for each other.

There can be multiple timesteps per token (dynamic depth / iterative refinement), but that's a different class of experiments — it requires determining when to stop. That's not what we're testing here.

Fix the experiment so the lateral is delayed by one position. Block 0 at position t gets block 1's output from position t-1 (or zeros at t=0). This is the only correct design for testing parallel block communication.
