# Performance note: CUDA graphs

You shouldn't need to be worried about CUDA kernel launches, because the whole thing should be one CUDA graph. The nested loop over timesteps and levels shouldn't be slow if it's captured in a CUDA graph — the Python loop only runs once during capture, then the whole thing replays as a single graph. Don't shrink the model to work around Python loop overhead; instead, capture the forward pass in a CUDA graph (or use torch.compile which does this automatically).
