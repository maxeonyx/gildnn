# Maybe one block = one kernel is fine

Maybe it is okay for one block to be one kernel, as long as it can communicate in and out with stale reads and writes. It doesn't matter if it reads the same incoming twice and misses one. It doesn't matter if it writes the same outgoing and the other one never reads it. If it overwrites an outgoing, it doesn't matter. We just run it as fast as we can, and it works.

I don't know exactly what this means, but I'm imagining little recurrent actors that just write in and out laterally. And they just run. They just run, run, run. And they read and they write. And some of them run slower than others. And some of them run faster.
