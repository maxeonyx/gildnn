# Why Python? Consider something GPU-native

I don't see why we should be implementing this in Python. If we can, we should be implementing this in something a bit more native to the GPU. That makes more sense to me.

For example, TF1 graphs (not traced), unlike tf.function which is traced. Other options: CUDA graphs (capture and replay without CPU), Triton (write kernels in Python-like syntax, compiles to GPU, no CPU fallback), custom CUDA, JAX jit, torch.compile with fullgraph=True (errors instead of falling back, but still traced). Triton sounds good. Point is, don't do it in a way where you can accidentally fall back to going back and forth and relaunching kernels all the time.
