# Dictation 2026-05-21-7

We should be using the Muon optimizer as soon as possible.

The reasoning: gradients explode because Jacobian matrices have singular values greater than one, and those compound multiplicatively across time steps. In a standard transformer the weight matrices are all different at each layer, so there's some statistical cancellation. In an RNN you don't get that cancellation — it's the same weight matrix applied T times, so the Jacobian product is literally W^T. If W drifts away from orthogonal even slightly, that drift gets amplified to the T-th power.

Muon keeps weight matrices near-orthogonal throughout training, not just at initialization. Orthogonal matrices have singular values exactly 1, so W^T also has singular values exactly 1 no matter how large T is. Gradients flow back arbitrarily far without exploding or vanishing.

This makes Muon particularly well-suited for RNN-like architectures where the same module is repeated across time. The orthogonalizing pressure is doing the most useful thing possible specifically for this architecture.

The k=8 and k=16 instability we just saw is probably a symptom of this — gradient explosion through time, not activation explosion. Muon should directly address it.

Concrete next action: swap in Muon as the optimizer and rerun the window size ablation (k=4, k=8, k=16) to see if the instability goes away.
