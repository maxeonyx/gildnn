[Discussion: torch.compile is a tracing JIT — it traces at runtime on the first call, then hands the graph to Triton for GPU kernels. It's similar to tf.function in TF2, which also traces and compiles to a static graph via XLA. JAX's jit is stricter — it requires pure functions with no side effects, which makes compilation more reliable with no silent fallback to eager. The strictness ladder is roughly JAX > tf.function ≈ torch.compile. JAX seems probably the right direction for core compiled code. However these are 2022-era options — I'd like to know what the 2026 options are, there may be something better.]

"Research into the 2026 compilation landscape: MLIR has won as the shared substrate — XLA, Triton, IREE, and Mojo are all converging on it. At the bottom of every path is LLVM → PTX (NVIDIA's virtual ISA). The stacks are: JAX → StableHLO (an MLIR dialect) → XLA → LLVM NVPTX → PTX. torch.compile → FX Graph → TorchInductor → Triton source → Triton (MLIR) → LLVM → PTX. The key difference between them is how cleanly and reliably they reach LLVM — JAX via a stable versioned graph IR with no graph breaks, torch.compile via a more fragile Python tracing step. A notable 2026 entrant is IREE — a fully MLIR-native compiler and runtime that never leaves MLIR until binary emission, architecturally the cleanest stack. The practical constraint: everything except PyTorch has Linux GPU as the primary target. JAX does not support Windows GPU natively. IREE same."
