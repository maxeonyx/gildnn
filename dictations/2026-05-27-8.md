# Dictation 2026-05-27-8

## Blocks are separate networks with separate optimizers

The blocks are each individual. I don't even see why we should share an optimizer. Each block gets its own loss and its own optimizer. They're separate networks that happen to communicate via stale (detached) laterals.

The current implementation sums all block losses into one scalar and does one backward pass through the whole model. That's wrong — it creates gradient coupling between blocks. Block 2's "predict 4 ahead" loss should NOT send gradient into block 0. They are independent learners.

If there's some reason we can't do this (e.g. the shared embedding table), that needs to be explicitly justified and presented to me. The default is: separate. The burden of proof is on coupling, not on independence.

The only shared thing that needs thought is the embedding table — which block's loss trains it? Probably block 0 (the output-facing block). Or maybe all blocks train it independently. But that's a design question that should be asked, not silently resolved by summing losses.
