# Dictation 2026-05-27-4

## ParallelDiagonalModel is a shell, not the model

`ParallelDiagonalModel` has the grid wiring — stale laterals, multi-rate, carry state — but it's missing everything that makes my design interesting:

- It has ONE global output head with global CE loss. I don't give a shit about that. Obviously a neural network trained with CE will learn. That's not what I'm testing.
- It does NOT do per-block local loss where higher blocks predict further ahead. That IS what I'm testing. That's the whole point.
- It does NOT use weight-tied normalized readout (it has a separate `nn.Linear` output head)
- It does NOT inject noise on laterals
- It predicts at the LAST position only, not per-position

The model needs: each block has its own tied-readout head (dot product against normalized embeddings), each block gets its own local CE loss predicting `rate` steps ahead, and we look at EACH BLOCK'S loss independently. Block 0 at rate 1 predicts next token. Block 1 at rate 2 predicts 2 ahead. Etc. Those per-block losses are what I care about. Does the higher block learn something different? Does it develop more abstract representations because it's predicting further ahead? THAT is interesting.

## Use CUDA graphs

The project validated 28% speedup from CUDA graphs. Use them by default in training. Don't regress on proven performance wins.

## The global CE is not the metric

Stop looking at global cross-entropy. I don't care whether the assembled model achieves good perplexity as a whole. I care whether the PIECES are doing their jobs:
- Is each block's local loss going down?
- Is the higher block learning different representations than the lower block?
- Does the multi-rate structure create timescale separation?

If the pieces work, the whole will work. If the pieces don't work, good global CE is meaningless — it just means one block is doing all the work and the others are dead weight.
